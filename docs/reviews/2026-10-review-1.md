## Findings

- [HIGH] SEC-01 src/unifi_carto/http.py:85 (with cli.py:331) - `--debug` configures the root logger at DEBUG, and httpcore then logs every raw response header tuple, including `Set-Cookie: TOKEN=...` from the legacy login and `X-CSRF-Token`. This breaks SPEC hard rule 3 ("never in ... `--debug` output"). The existing `test_secrets_never_logged` misses it because respx bypasses httpcore - evidence: test_review_secrets.py::test_sec01_debug_log_has_no_session_cookie_or_csrf (real TLS server on 127.0.0.1) - fix: in `cli.main`, pin `logging.getLogger("httpcore")` (and `"httpx"`, which logs full URLs at INFO) to WARNING even with `--debug`, or attach a filter. - [HIGH] COL-01 src/unifi_carto/collect.py:155-166 - `TlsPinMismatch` (a `CartoError`, not an `ApiError`, raised in `http.py:343` while the client is built) is not caught per target. ## Observations (no proof test; judgment calls or not reachable through public APIs)

- `http._LEGACY_AUTH_MSGS` (`NoPermission`, `LoginRequired`, `Unauthorized`) and `legacy._AUTH_MESSAGES` (`LoginRequired`, `NoPermission`, `Invalid`) disagree. With the real transport, `api.err.Invalid` becomes a plain `ApiError` in `_decode`, so `Legacy`'s handling of it is dead code and no login fallback happens. Decide on one set and share it.
- `login_legacy` POSTs are retried on 429/502/503/504 and transport errors (`http.py:182-200`), so credentials can be sent up to 4 times, and a POST is retried after an ambiguous transport failure. Consider not retrying the login.
- `_send` validates the login capability and path but not the origin. Code that imports the private `_LOGIN_CAP` could POST the password, with the `X-API-KEY` header still attached, to any host. Also check `urlsplit(url).netloc == urlsplit(self.base_url).netloc`.
- Server-supplied ids are interpolated unescaped into paths: site/device/network ids in `integration.py:289-316` and the host id in `sitemanager.connector_base_url`. A hostile or buggy id containing `/../`, `?` or `#` redirects a GET, still to the same host with the same key. Use `quote(id, safe="")`.
- Two `[[console]]` entries with the same `host_id` (or one by `host_id`, one by name) are both collected, so the inventory holds duplicate devices under one console id. Reject duplicates in `plan_targets`.
- Per reference.md, WiFi broadcast details carry `securityConfiguration.passphrase` (and `radiusConfiguration`). The builder reads only `type`, and the scrubber drops `pass*`/`*secret*`, so nothing leaks today, but the PSK sits in `OfficialSnapshot.wlans` in memory and in anything that dumps snapshots unscrubbed.
- With fingerprint pinning, `build_ssl_context` re-fetches the peer certificate for every client: official and legacy, so 2 handshakes per local console. That's harmless, but it widens COL-02.

## Checked and fine

- Read-only runtime guard: non-GET/HEAD refused before any request; bodies refused on GET/HEAD; `follow_redirects=False` (3xx raises, so no method-changing redirects); the httpx client is name-mangled and `__slots__` blocks attribute injection; there are no event hooks; a subclass calling `_send("POST", ...)` without the capability is refused; `trust_env=False`.
- Secrets in exceptions and warnings: `ApiError.url` is the path only (never the query or host), transport exceptions are raised `from None`, `ReadOnlyClient.__repr__` hides the key, config errors name env vars and paths, not values, and the secret-file mode check rejects group/other bits.
- TLS: `normalize_fingerprint` handles case, `sha256:` prefix, colons and dashes, and rejects SHA-1 (40 hex) and other lengths. The pinned context trusts exactly the fetched leaf (no system CAs), so a different certificate on the real connection fails. The fetch-then-connect race therefore isn't exploitable. `ca_cert` loads only the given file (no system store). api.ui.com and connector targets use system trust (`tls=None`). Python handles SNI for IP `local_url`s (no SNI sent for IPs; with pinning, hostname checking is off).
- `Retry-After`: negative -> 0, huge/`inf` -> 60 s cap, `nan` -> 0, HTTP-date handled. Site Manager pagination has a page cap and detects repeated `nextToken`.
- Renderer: every user string in HTML labels goes through `html.escape`. `<img onerror>`, `"`, `]]>` and `&amp;` render as text (cell values, checked by parsing the output). Page names are plain text. No user data reaches style strings. Long names, zero devices, devices without IPs and the empty inventory all render well-formed.
- Builder: link dedup when both ends report with numeric ports; LAG with LLDP on one member only (a second link sharing `lag_id`, correct orientation); mesh only for AP-to-AP wireless; official-only AP-to-AP stays `unknown` (A1.8); devices without MAC skipped with a warning; `tagged_vlan_mgmt=custom` minus excluded minus native (A1.5); port override > profile ordering; output sorted by id, so deterministic regardless of unicode names; `None` (unknown) vs `[]` (block_all) preserved.
